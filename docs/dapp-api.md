# dApp JSON-RPC API

This node exposes a small Ethereum-flavoured JSON-RPC surface for dApps that
need lightweight interoperability. Methods follow the [JSON-RPC 2.0
specification](https://www.jsonrpc.org/specification) and mirror common
Ethereum semantics where sensible.

## Available methods

| Method | Description |
| --- | --- |
| `web3_clientVersion` | Returns the `simple-chain` version string. |
| `eth_chainId` | Chain identifier encoded as a hex quantity. |
| `eth_blockNumber` | Current best block height as a hex quantity. |
| `eth_getBalance(address, [blockTag])` | Returns the balance of an address. Supports Base58 or 20-byte hex addresses. Balances default to the latest confirmed state; passing `"pending"` includes mempool updates. |
| `eth_getBlockByNumber(blockTagOrNumber, fullTransactions)` | Looks up a block by tag (`latest`, `pending`, `safe`, `finalized`, `earliest`) or number. Set `fullTransactions` to `true` to embed transaction objects. |
| `eth_sendRawTransaction(payload)` | Submits a raw transaction JSON payload (UTF-8 string or hex). Returns the transaction hash if accepted. |
| `getBalance(address)` | Legacy method returning `{ "balance": <double> }`. |
| `getBlockByNumber(height)` | Legacy method returning a raw block or `{ "error": "Block not found" }`. |
| `sendTransaction(payload)` | Legacy wrapper returning `{ "hash": <hex> }`. |

## Error handling

The node now surfaces JSON-RPC compliant errors:

- `-32601` – method not found
- `-32602` – invalid params
- `-32000` – transaction rejected or malformed payloads

Legacy methods continue to return the historical payloads to preserve
backwards compatibility.

## Address normalisation

The API accepts:

- Base58-check addresses generated by the wallet
- Hex-encoded 20-byte payloads (with or without the `0x` prefix)

Hex inputs are converted to Base58 internally using the same helper the wallet
relies on. Invalid addresses resolve to a zero balance.

## Balance semantics

Unless otherwise specified, balances reflect the confirmed UTXO snapshot. When
`"pending"` is supplied as the block tag, the handler overlays transactions
sitting in the mempool so dApps can provide instant feedback after signing.

## Block tags

| Tag | Notes |
| --- | --- |
| `latest` | Best known block |
| `pending` | Alias for `latest`; also enables pending balance calculations |
| `finalized` / `safe` | Map to the latest block in this PoW chain |
| `earliest` | Genesis block |

## Payload encoding

`eth_sendRawTransaction` accepts either a raw JSON string or a hex-encoded JSON
payload. Hex strings are decoded as UTF-8 bytes before parsing.
